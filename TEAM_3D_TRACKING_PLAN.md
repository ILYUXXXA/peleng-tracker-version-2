# Peleng Tracker: текущее состояние и план 3D-сопровождения

Статус на 2 ноября 2026 года. Документ нужен для синхронизации команды перед хакатоном: что мы строим, почему изменили первоначальный подход, что уже работает и какие части ещё требуют проверки.

## Что мы хотим показать на хакатоне

Основной результат — восстановление положения и траектории движущегося объекта в трёхмерном пространстве по нескольким синхронизированным и откалиброванным камерам.

Пользователь должен иметь возможность:

- обработать запись с нескольких камер;
- получить траекторию объекта в координатах `(x, y, z)` в метрах;
- открыть результат в интерактивном 3D-редакторе;
- вращать и масштабировать 3D-сцену;
- перематывать запись и переходить по кадрам;
- воспроизводить её со скоростью от `0.25×` до `5×`;
- одновременно видеть выбранное видео и проекцию 3D-траектории на него;
- видеть скорость, ускорение и качество текущего измерения;
- выгрузить траекторию в CSV или JSON.

Проекция людей на плоскость пола сохраняется как дополнительный режим, но не является основным решением.

## Почему первоначального World View недостаточно

Первая демонстрация была построена на видео EPFL с людьми. YOLO и локальный tracker находили людей отдельно в каждой камере, после чего система пыталась объединить локальные треки.

На практике один человек часто отображался несколькими точками. Например, при четырёх людях World View мог показывать семь точек. Причины:

- локальные ID разных камер сами по себе не обозначают одного человека;
- сопоставление между камерами иногда не находило пару;
- для несопоставленных наблюдений создавались отдельные planar fallback-точки;
- положение человека оценивалось на плоскости пола, поэтому это не было полноценным восстановлением 3D.

В старом режиме уже исправлены часть геометрии и one-to-one assignment, однако для хакатонной задачи основной контур теперь строится вокруг настоящей многокамерной триангуляции.

## Основной демонстрационный набор данных

Для первого воспроизводимого результата выбран публичный датасет [**DPJAIT — Multimodal Dataset for Indoor 3D Drone Tracking**](https://zenodo.org/records/14748573):

- четыре синхронизированные внешние RGB-камеры в реальных сценах;
- внутренние и внешние параметры камер;
- готовые 2D-детекции дронов;
- эталонные 3D-координаты от Vicon;
- лицензия CC BY 4.0;
- полный архив занимает 15.7 ГБ и не будет добавляться в Git.

Актуальный архив называется `DPJAIT.7z`, контрольная сумма MD5 — `441679870cd2c989e352437f15cce139`.

Первый целевой сценарий — `R02_D1`: один дрон, 1514 кадров, около 61 секунды. В опубликованном baseline для него указана медианная ошибка 3D-положения 6.3 см.

Сначала используем готовые 2D-наблюдения датасета. Это позволяет отдельно проверить синхронизацию, калибровку, триангуляцию, фильтрацию и редактор. Детектор по пикселям будет подключаться через тот же интерфейс наблюдений позднее.

## Архитектура

```text
Синхронные видео и 2D-наблюдения
                │
                ▼
      Калибровка всех камер
                │
                ▼
 Multi-view triangulation в каждом кадре
                │
                ▼
 Kalman filter: position + velocity + acceleration
                │
                ▼
     Сохранённая replay-сессия
                │
        ┌───────┴────────┐
        ▼                ▼
  3D-редактор      Видео с проекцией
```

У всех источников будет общий контракт 2D-наблюдения:

```text
frame_index, timestamp, object_id, camera_id, u, v, confidence
```

Источником может быть:

- готовая разметка DPJAIT;
- ArUco-маркер с известным ID;
- YOLO и локальный tracker;
- другой детектор, если команда решит его заменить.

## Что уже реализовано

### Существующий live-контур

- подключение нескольких RTSP, HTTP и телефонных источников;
- Ultralytics YOLO;
- BoT-SORT и DeepSORT;
- локальные треки с ID, ограниченным конкретной камерой;
- межкамерное one-to-one сопоставление через LAP/Hungarian assignment;
- триангуляция по калибровке и planar fallback;
- выбор конкретной цели или класса объектов;
- диагностические данные по fused и fallback-трекам;
- WebSocket-метаданные и WebRTC-видео.

### Новый offline/replay-контур

- формат локального demo bundle с `scenario.yaml`;
- проверка файлов, камер, наблюдений и калибровки;
- детерминированная обработка одинаковых frame index без RTSP и Docker;
- multi-view DLT-триангуляция минимум по двум камерам;
- проверка положительной глубины и reprojection error;
- 9-мерный Kalman filter:
  - позиция `(x, y, z)`;
  - скорость `(vx, vy, vz)`;
  - ускорение `(ax, ay, az)`;
- краткосрочный прогноз при пропуске измерения;
- сохранение полной траектории в `trajectory.json`;
- оценка результата относительно необязательного 3D ground truth;
- экспорт CSV и JSON;
- read-only replay API.

Доступные команды:

```bash
uv run peleng-tracker demo import-dpjait demo/dpjait-source/Real_Data/R02_D1 \
  --sequence R02_D1 --output demo/dpjait-r02
uv run peleng-tracker demo validate demo/<scenario>
uv run peleng-tracker demo process demo/<scenario>
uv run peleng-tracker demo evaluate demo/<scenario>
uv run peleng-tracker demo run demo/<scenario>
```

Импортёр DPJAIT связывает калибровку, четыре видео, готовые YOLOv5-детекции и Vicon в один bundle. Исходные AVI автоматически преобразуются в H.264 MP4 для браузера.

### 3D-редактор

В интерфейс добавлена вкладка `3D Replay`:

- интерактивная сцена на Three.js и React Three Fiber;
- метрическая сетка и оси;
- вращение, перемещение и масштабирование камеры;
- текущая позиция объекта;
- траектория с градиентом по давности: старый участок тёмный, текущий — яркий;
- отдельная панель выбранной камеры;
- проекция рассчитанной 3D-траектории обратно на видео;
- общий timeline для видео и 3D;
- play/pause, шаг на один кадр и скорости `0.25×`, `0.5×`, `1×`, `2×`, `5×`;
- текущие координаты, скорость, ускорение, quality, frame index и камеры-источники;
- ссылки на выгрузку CSV и JSON.

Тяжёлые зависимости Three.js загружаются только при открытии редактора, а не вместе с основной страницей.

## Что уже проверено

На синтетических калибровках и реальной последовательности `R02_D1` проверены:

- восстановление известной 3D-точки;
- отклонение точки с отрицательной глубиной;
- обработка нескольких синхронных наблюдений;
- прогноз на пропущенном кадре;
- API траектории, видео и экспорта;
- совместимость с существующими тестами live-контура.

Для DPJAIT зафиксированы две неочевидные детали формата:

- `cam_or_x/y/z` — Rodrigues-вектор OpenCV;
- `cam_x/y/z` — OpenCV `tvec` преобразования world-to-camera, а не положение камеры в мировых координатах.

Vicon записан с частотой 100 Гц, видео — 25 FPS. Для `R02_D1` используется временное смещение `-3` Vicon-отсчёта. Эталонный визуальный центр получен из центра четырёх маркеров со смещением на 100 мм вниз, указанным на схеме маркерного креста в архиве.

## Что ещё не сделано

### 1. Ручная проверка редактора

Production build проходит, но редактор ещё не проверялся визуально на настоящем видео. После создания DPJAIT bundle нужно проверить:

- совпадение 3D-точки и дрона на всех камерах;
- направление осей и единицы измерения;
- плавность перемотки и воспроизведения на `5×`;
- читаемость градиента;
- корректность camera switching;
- поведение на пропущенных наблюдениях.

### 2. Компактный GitHub slice

Полный датасет в репозиторий не попадёт. После просмотра `R02_D1` команда выберет выразительный фрагмент ориентировочно на 10–20 секунд. Slice должен содержать:

- четыре синхронных видео;
- калибровку;
- нормализованные 2D-наблюдения;
- эталонную 3D-траекторию;
- `scenario.yaml`;
- лицензию и ссылку на исходный датасет.

Конкретный отрезок пока не выбран: это будет сделано после просмотра полной записи.

### 3. Детектор и live-совместимость

После того как геометрический контур подтверждён на разметке, можно подключить:

- готовый детектор дрона;
- ArUco как контролируемый вариант для собственных камер;
- запись live-видео и телеметрии в тот же формат replay-сессии.

Live-режим не блокирует первый хакатонный MVP: основной демонстрационный путь — заранее обработанная запись с возможностью показать весь процесс вычисления и метрики.

## Ближайший порядок работы

1. Запустить `demo/dpjait-r02` и визуально проверить редактор на всех четырёх камерах.
2. Проверить плавность скорости и ускорения на полном минутном фрагменте.
3. Вместе выбрать короткий GitHub slice.
4. Подготовить сценарий презентации и зафиксировать ожидаемые метрики.
5. После стабильного offline-демо подключить детектор по пикселям или ArUco через тот же контракт наблюдений.
